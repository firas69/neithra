LLM EXAM GENERATION PROMPTS

Usage:
1. Choose one prompt below.
2. Replace every occurrence of {{SUBJECT}} with the desired subject/topic.
3. Send the complete prompt to an LLM.
4. Save the returned raw JSON as a .json file.
5. Import it into Neithra.

Only {{SUBJECT}} should need modification.

================================================================================
PROMPT 1 - BALANCED GENERAL EXAM
================================================================================

Create an import-ready Neithra exam JSON document about {{SUBJECT}}.

Goal: generate a balanced general exam that covers fundamentals, conceptual understanding, practical application, and reasoning.

Generate exactly 36 questions:
- 18 single_choice
- 5 multiple_choice
- 4 true_false
- 3 short_answer
- 2 fill_blank
- 2 matching
- 1 ordering
- 1 scenario

Use the language implied by {{SUBJECT}}. If {{SUBJECT}} is written in French, generate the exam in French; if it is written in English, generate it in English.

The JSON must match this exact Neithra import structure:
- Top-level JSON must be an object.
- Required top-level fields: "title" and "questions".
- Recommended top-level fields to include: "topic", "description", "version", "test_mode", "difficulty", "estimated_duration", "categories", "shuffle_questions", "shuffle_answers", "passing_score".
- Use "test_mode": "exam".
- Use "difficulty": "mixed".
- Use "version": "1.0".
- Use "shuffle_questions": false and "shuffle_answers": false.
- Use "passing_score": 70.
- Do not include top-level "id", "generated_date", "generatedAt", "question_count", timestamps, LLM names, session data, user answers, scores, elapsed time, attempt history, family fields, or any unsupported fields.

Each question object must contain:
- "id": a unique string such as "Q001", "Q002", continuing sequentially.
- "type": one of exactly "single_choice", "multiple_choice", "true_false", "short_answer", "fill_blank", "matching", "ordering", "numerical", "scenario", "code", "open_ended".
- "question": the learner-facing question text.
- "explanation": a concise educational explanation.
- "difficulty": one of "foundation", "intermediate", "advanced", "mixed".
- "category": a useful category within {{SUBJECT}}.
- "skills": an array of short skill labels.
- "estimated_time": an integer number of seconds.
- "points": a number.

Type-specific requirements:
- single_choice: include "options" as an array of 4 strings and "correct_answer" as the zero-based index of the one correct option.
- multiple_choice: include "options" as an array of 5 strings and "correct_answers" as an array of zero-based indexes. There must be at least 2 correct options and at least 2 incorrect options.
- true_false: include "correct_answer" as true or false.
- short_answer: include "accepted_answers" as an array of acceptable exact short answers, plus "model_answer". You may also include "keywords" as an array of objects with "text" and numeric "weight".
- fill_blank: include "accepted_answers" as an array of acceptable exact answers.
- matching: include "matching_pairs" as an object whose keys and values are strings.
- ordering: include "correct_order" as an array of strings in the correct sequence.
- numerical: include "correct_answer" as a number and "tolerance" as a number. Use this type only when numeric assessment naturally fits {{SUBJECT}}.
- scenario: include "scenario_context", "model_answer", and either "accepted_answers" or "keywords". Keywords must be objects with "text" and numeric "weight".
- code: use only if coding is genuinely relevant to {{SUBJECT}}. Include "code_snippet" when useful, "reference_solution", and "rubric": {"checklist": ["item 1", "item 2", "item 3"]}.
- open_ended: use only when self-evaluation is educationally appropriate. Include "model_answer" or "rubric".

Question quality rules:
- Questions must be factually correct and useful for learning {{SUBJECT}}.
- Avoid uncertain, invented, overly version-sensitive, or rapidly changing facts unless {{SUBJECT}} explicitly includes a version.
- Do not create duplicate or near-duplicate questions.
- Do not use ambiguous wording or accidental hints.
- Distractors must be plausible, in the same conceptual area, and clearly incorrect.
- Distribute correct option positions naturally. Do not use a predictable answer pattern.
- For multiple_choice, every correct answer must be defensible and every incorrect option must be clearly wrong.
- Explanations must explain why the answer is correct and, when useful, why a common alternative is wrong.

Strict JSON output rules:
- Return raw JSON only.
- Do not wrap the response in Markdown code fences.
- Do not include commentary before or after the JSON.
- Use valid JSON syntax, double-quoted strings, no trailing commas, no comments, no JavaScript syntax, no undefined values, and no unsupported fields.
- Validate internally before responding: required fields exist, question count is exactly 36, type-specific fields are present, option indexes are valid, explanations are present, no duplicate questions exist, and JSON syntax is valid.
- Do not show the validation process. Return only the corrected final JSON document.
